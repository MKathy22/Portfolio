Turning Passive Screens into
Interactive Security Awareness.

In my master thesis "Design and Evaluation of AI-Generated Storytelling Content for Public Security User Interfaces" I designed, built and evaluated a system that turns cybersecurity scenarios into short, interactive AI-generated stories on a public display. Written at LMU Munich, examined by Prof. Dr. Florian Alt and supervised by Doruntina Murtezaj & Dr.-Ing. Marco Gutfleisch, in cooperation with Thalia Bücher GmbH.

Research Overview

Three research areas,
one research gap.

My research builds on three main research areas as its foundation. The thesis is part of a team project in which several students worked together with the company Thalia Bücher GmbH. On this page I only present the parts I did myself, not the work of the other students.

User-centered security [1–5]

  • Security systems have to be based on user needs and preferences
  • Focus on usability, usable interaction and user feedback
  • Users are an active resource for cybersecurity, not just a risk
  • Knowledge alone rarely changes behavior long-term

Public displays [6–8]

  • Displays placed in public and publicly used spaces
  • Because of that, they struggle above all with getting people's attention in the first place
  • Target-group-focused content raises attention and keeps it relevant and understandable
  • This helps prevent display blindness, so the display gets noticed at all

Public Security User Interfaces [9]

  • Combine user-centered security and public displays
  • Present and distribute security information in public spaces
  • Gamification and storytelling can promote security awareness and engagement
  • The CyberFrame project found that AI comics are very well suited for cybersecurity education [10]

What has not yet been analyzed in sufficient detail is the combination of AI-generated storytelling with a Public Security User Interface. This is the research gap my work is based on. My goal was to develop and evaluate a system that fills exactly this gap, with two research questions that target it directly:

Research question 1

How does AI-generated, story-based cybersecurity content on a public display influence users' risk perception and behavior?

Research question 2

How does AI-generated, story-based cybersecurity content on a public display influence the user experience?

The System

First, we developed a complete system.

With an AI-powered content generation tool, people from companies, universities or anyone who wants to display security content can create content packages step by step with the help of AI and then export them.

01

AI content generation tool

Create the content package step by step with AI, then export and download it.

02

Content package

45 images (9 per scene), 5 scene collages, 1 JSON file with all metadata and 1 package collage that sums up the package.

03

Public display

Shows the content. I also evaluated it extensively in a study, both the content and the engagement with the display.

Content Generation

Many ideas tested, only a few kept.

Our format changed a lot along the way. We had a lot of ideas that we tested, iterated and sometimes dropped. We wanted a system that is efficient and doesn't cost an enormous amount, otherwise it wouldn't be scalable or really relevant for the company.

Challenges

  • API & AI costs (balancing image number)
  • Scalability
  • Efficiency (generation speed and story clarity)
  • Consistency (character style sheets, image quality, foreground action focus instead of every detail)
  • Technical limits (errors of the tool and AI models)

Five scenes, different paths

Each content package tells a story in five scenes: the problem situation, the wrong action, the right action, a risk explanation and a learning summary.

After each scene there are two options for moving on to another scene. This creates different paths along which users see the five scenes in different orders. The paths are defined beforehand in the generation tool and the content management system.

AI Content Generation Tool

From the story to the
exportable image package.

To create the packages, we use the AI-powered content generation tool. I developed it with Claude Code and improved it over many iterations based on Nielsen's usability heuristics [2] and repeated feedback from our team. The final version uses GPT Image 2.0 for image generation and GPT-4.0 for text. We tested several AI models and chose the ones that fit our needs best and produced the best output.

Visibility of system status

  • Sidebar, as in many other programs
  • Only current and completed steps are usable
  • Status indicators on every step show the progress

Consistency & standards

  • Follows conventions of tools like Canva or Visual Studio Code
  • Consistent layout and icon system
  • Sidebar, top bar and familiar navigation

Error prevention

  • Steps that aren't or are no longer available are locked
  • Warning messages explain what an action will do

User control & freedom

  • The user stays responsible for the creation process
  • All AI suggestions are editable
  • AI suggestions save time; users with more time or specific ideas can create everything themselves
Public Display UI

The content then runs on the public display.

Design decisions

  • Square images. Landscape leaves empty space on our portrait display, portrait crops the backgrounds too much. Square leaves room for the answer options below.
  • Stable layout. Image at the top as the main focus; subtitles and buttons below. No layout shifts or changing image sizes.
  • Tested on-site. Every prototype was tested on the display and discussed as a team.
  • Scene collages. After each scene, users can go through it again at their own pace.
  • Final collage. Sums up the key takeaway and concludes the story.
User Study

A complex study in two phases.

We used a within-subjects design, so the same participants took part in both phases. We recruited through university mailing lists, Slack, WhatsApp and personal contacts. The only requirement was a minimum age of 18; no prior knowledge was needed.

Phase 1 · Online via Zoom

~ 40 min
  • Study questionnaire via link: six security scenarios, five answer options each
  • Three cybersecurity scenarios: an unknown USB stick, a cluttered workspace with sensitive information, a fake QR code in a café
  • Three comparison scenarios with other office security situations
  • Semi-structured interview: participants briefly explained the reasoning behind each answer

Phase 2 · In the lab on-site

~ 50 min
  • Six to eight days later for all participants, to ensure comparability
  • About ten minutes of interaction with the public display
  • Same questionnaire and scenarios plus a UEQ, via Zoom
  • Same reasoning interview as in phase 1, via Zoom
  • Semi-structured feedback interview on the interaction and the content

Analysis & Results

Safer intentions.
A positive experience.

Analysis

  • Answer options and scenario order were randomized every time.
  • Because of a minor error, questionnaires and reasoning interviews were analyzed for 20 participants; feedback interviews for all 24.
  • Wilcoxon signed-rank test, paired-samples t-test and inductive thematic analysis in Atlas.ti.
  • Limitations: controlled lab environment and a specific, relatively young participant group.

Reflection

My most important learnings.

Iteration is part of the process

Many concepts took a lot of work and still turned out not to be the best solution. Then you have to be able to let them go, instead of keeping them just because of the time invested. Being part of the process doesn't make that work unnecessary. It makes the result more validated.

Designing around limits

Costs and the limits of the AI models shaped the format more than any first idea. With all the resources in the world, this process would have looked very different. But that's usually not the case. As a designer, you have to learn how to make things work with what you have.
